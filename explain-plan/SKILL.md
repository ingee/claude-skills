---
description: 다음 작업의 구현 계획과 검증 계획을 설명할 때 사용
---

0. **설명에 앞서 먼저 `git status`로 현재 작업 디렉토리에 커밋되지 않은 변경 사항이 있는지 확인한다.** 변경 사항이 있으면 계획 설명으로 바로 넘어가지 말고, 어떤 파일이 변경/추가되어 있는지 요약해 경고하고 먼저 커밋할지 물어본다. 사용자가 답을 줄 때까지(커밋하거나, 그대로 진행하라고 확인해줄 때까지) 1번 이하로 넘어가지 않는다. Working tree가 clean하면 이 경고 없이 바로 진행한다.

1. `CLAUDE_worklist.md`에서 체크되지 않은(`- [ ]`) 첫 항목을 다음 작업으로 확인한다. 해당 항목의 "완료 기준"과, CLAUDE.md에서 그 항목이 참조하는 API 명세/DB 명세 원문을 함께 읽는다.

2. 같은 종류의 이전 항목이 있으면 그 구현(컨트롤러/서비스/리포지토리/테스트)을 열어 재사용 가능한 패턴을 파악한다 — 이 프로젝트는 비슷한 API끼리 골격을 그대로 재사용하는 경우가 많다(예: Private `DELETE`와 Admin `revoke`, `security` 발송과 `test` 발송).

3. **구현 계획을 파일 단위로 제시한다**: 새로 만들거나 수정할 파일 목록과, 각 파일이 무엇을 하는지. 기존 파일을 재사용하는 결정(예: 응답 DTO 공유)과 새로 분리하는 결정을 구분해서 그 이유를 밝힌다.

4. **스펙에 명시되지 않아 판단이 필요한 부분(ambiguity)이 있으면 마음대로 결정하지 말고 짚어서 확인받는다** — 특히 다른 데이터/필드 값에 영향을 주는 결정(예: enum 값 선택, 기본값 처리 방식)일수록 구현 전에 확인한다.

5. **검증 계획을 제시한다**: 완료 기준을 어떤 테스트 케이스들로 확인할지, 기존 테스트 파일 중 어떤 걸 패턴으로 재사용할지, 새로 필요한 테스트 헬퍼가 있는지.

6. 이 skill은 설명까지만 한다 — 실제 파일 작성/수정은 사용자가 계획에 동의한 뒤에 시작한다.
