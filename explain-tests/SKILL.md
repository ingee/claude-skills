---
description: 테스트 코드의 위치와 각 테스트가 무엇을 왜 검증하는지 설명할 때 사용
---

대상 테스트 파일(사용자가 지정한 파일, 없으면 방금 작성/수정한 테스트 파일)에 대해 다음을 설명한다.

1. **위치**: 파일의 절대 경로(또는 프로젝트 루트 기준 상대 경로)를 먼저 밝힌다. 같은 디렉터리에 참고할 만한 다른 테스트 파일이 있다면 함께 언급한다.
2. **테스트 종류**: 통합 테스트인지 단위 테스트인지, 어떤 어노테이션/베이스 클래스로 그렇게 되는지(예: `@SpringBootTest`+`@AutoConfigureMockMvc`+실제 DB vs. Mockito로 의존성을 다 가짜로 대체) 짧게 밝힌다.
3. **테스트 케이스별 설명**: 테스트 메서드마다 "무엇을 검증하는지"와 "왜 이 케이스가 필요한지(어떤 스펙/버그/설계 결정과 연결되는지)"를 표로 정리한다. 코드를 그대로 읽어주는 게 아니라, 이름만 봐서는 안 드러나는 의도(엣지 케이스, 스펙의 특이한 규칙, 과거에 발견된 함정 등)를 짚는다.
4. **헬퍼 메서드**: 테스트 하단의 private 헬퍼(픽스처 생성, 요청 빌더 등)가 있으면 무슨 역할인지, 다른 테스트 파일과 공유되는 패턴인지 간단히 짚는다.
5. 사용자가 이미 알고 있을 배경(예: 직전 대화에서 설명한 개념)은 반복하지 말고, 그 설명을 참조하는 정도로 짧게 넘어간다.

표/목록 위주로 간결하게 작성하고, 코드 전체를 다시 인용하지 않는다 — 파일 경로와 라인 번호로 참조한다.
